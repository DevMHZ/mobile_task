# Mobile Task — Real Estate App (Flutter)

تطبيق عقاري احترافي مبني بواسطة **Flutter** يدعم اللغتين **العربية (RTL)** و**الإنكليزية (LTR)**، متكامل مع واجهة **DummyJSON API**، ومصمم وفق أفضل ممارسات هندسة البرمجيات وتجربة المستخدم مستوحى من تصميم Figma المعتمد.

## 🚀 متطلبات التشغيل والتثبيت

### المتطلبات الأساسية
- **Flutter SDK:** الإصدار `3.47.7` أو أحدث (قناة stable).
- **Dart SDK:** الإصدار `3.13.5` أو أحدث.
- **Android SDK:** (API 34/35) لتشغيل Android أو **Xcode** (15+) لتشغيل iOS أو **Chrome** لتشغيل Web.

### خطوات التثبيت والتشغيل

1. **استنساخ المستودع وتثبيت الاعتماديات:**
   ```bash
   git clone https://github.com/DevMHZ/mobile_task.git
   cd mobile_task
   flutter pub get
   ```

2. **توليد ملفات الترجمة والتعريب:**
   ```bash
   flutter gen-l10n
   ```

3. **تشغيل التطبيق على المحاكي أو الجهاز المتصل:**
   ```bash
   # تشغيل مع ملف الإعدادات الافتراضي
   flutter run --dart-define-from-file=env/dev.json

   # أو التشغيل على متصفح Chrome
   flutter run -d chrome --dart-define-from-file=env/dev.json
   ```

4. **تثبيت CocoaPods لـ iOS (عند الحاجة):**
   ```bash
   cd ios
   pod install
   cd ..
   ```

## ⚙️ إعداد عنوان API والتخصيص

عنوان API مضبوط افتراضياً على خادم DummyJSON المعتمد في ملف `env/dev.json`:
```json
{
  "API_BASE_URL": "https://dummyjson.com"
}
```

ويمكن تجاوزه مباشرة عبر سطر الأوامر دون تعديل الكود:
```bash
flutter run --dart-define=API_BASE_URL=https://dummyjson.com
```

## 🏛️ بنية المشروع وهندسة الكود (Architecture)

يعتمد المشروع نمط **Clean Architecture** مع فصل صارم للمسؤوليات بالاعتماد على:
- **إدارة الحالة (State Management):** `flutter_bloc` (`Cubit`) لتحقيق تدفق بيانات أحادي الاتجاه (Unidirectional Data Flow) وسهولة الاختبار والعزل التام عن طبقة العرض.
- **حقن الاعتماديات (Dependency Injection):** `get_it` لتجميع الخدمات عند نقطة الدخول (`Composition Root`) دون تلويث الودجات.
- **طبقة الشبكة (Networking):** `dio` مع معالجة مهل الاتصال وتصنيف الأخطاء إلى كائنات `AppFailure`.
- **التخزين المحلي (Local Storage):** `shared_preferences` الحديث عبر `SharedPreferencesAsync` لحفظ اللغة والمفضلة.

### الهيكل التنظيمي للمجلدات:

```text
lib/
├── core/
│   ├── config/              # إعدادات التطبيق وعناوين الخادم وثوابت المهلة

│   ├── localization/        # محولات الأرقام والعملات وتصنيف الأخطاء المعربة
│   ├── network/             # عميل Dio، معالجة الاستثناءات ومحولات الفشل
│   ├── theme/               # الرموز البصرية، الألوان الموحدة، والخطوط
│   └── widgets/             # ودجات الشيمر المتقدمة، الصور الشبكية، وحالات الخطأ والفراغ

│   │       └── ui/          # شاشات العرض، ورقة التصفية المتقدمة، وبطاقات العقارات
```

## 💎 أبرز المزايا والتحسينات المنجزة

### 1. ورقة تصفية متقدمة مطابقة لتصميم Figma (Filter Sheet)
- **مخطط بياني لتوزيع الأسعار (Price Histogram):** أعمدة تفاعلية توضح كثافة الوحدات السعرية في السوق.
- **سلايدر نطاق السعر مع ملصقات متحركة:** يعرض مؤشرات السعر تحت مقبضي السلايدر بدقة ومباشرة.
- **أزرار اختيار نوع العقار (Property Type Pills):** كبسولات أنيقة تدعم الاختيار المتعدد (شقق، تاون هاوس، منازل، كوندو، دوبلكس، استوديو).
- **عدادات تفاصيل المنزل (Home Details Steppers):** أزرار تفاعلية لزيادة وإنقاص عدد غرف النوم والحمامات.
- **سلايدر مساحة البناء (Building Size):** تصفية دقيقة بالمتر المربع/القدم المربعة.

### 2. نظام Shimmer Loading واقعي واحترافي (AppShimmer)
- تأثير لمعان ناعم بتردد 60 إطار في الثانية يعتمد على `ShaderMask` و`SlidingGradientTransform`.
- هياكل هيكلية (Skeletons) واقعية تعكس بدقة شكل بطاقات العقارات، ومطياف الصور، وقوائم التوصيات.
- متوافق ومضبوط لعدم تعطيل اختبارات الواجهات (`Widget Tests`) وضمان استقرار `pumpAndSettle`.

### 3. قائمة الإجراءات الفاخرة (Product Actions Menu)
- زر دائري عائم أسفل زر المشاركة يوفر وصولاً سريعاً للمشاركة، التعديل، والحذف.
- شارات ملونة لكل إجراء، ومربعات حوار تأكيدية حديثة ومريحة للمستخدم.

### 4. تجربة تبديل لغات فائقة السلاسة ودعم RTL/LTR كامل
- **زر تبديل سريع في شريط التطبيق:** تبديل فوري بنقرة واحدة بين العربية والإنجليزية.
- **بطاقة إدارة اللغة في الإعدادات:** بطاقات اختيار تفاعلية تبرز اتجاه النص ومؤشرات AR/EN.
- خطا **Rubik** للإنجليزية و **IBM Plex Sans Arabic** للعربية مدمجان محلياً، مع مراعاة كاملة لانعكاس الواجهات، وتنسيق الأرقام والعملات، وقواعد الجمع (ICU Plurals).

### 5. نظام مفضلة متفاعل وسريع الاستجابة
- تحديث فوري للأيقونة دون إعادة بناء القوائم كاملة باستخدام `BlocSelector`.
- توحيد درجات لون القلب الأحمر (`0xFFFF385C`) لمنع التباين أو الخلل البصري.
- حفظ التفضيلات محلياً واستعادتها تلقائياً عند فتح التطبيق.

## ⚠️ قيود وافتراضات DummyJSON API

### ربط بيانات المنتجات بواجهة عقارية

لا توفر DummyJSON واجهة عقارية، لذلك تُستخدم منتجاتها كعناصر عرض تجريبية داخل واجهة مستوحاة من تصميم Figma العقاري:

| حقل DummyJSON | الاستخدام في الواجهة |
|---|---|
| `title`, `description`, `price`, `rating`, `images`, `thumbnail` | بيانات البطاقة والتفاصيل كما هي من المصدر (بالإنجليزية من الخادم) |
| `category` | شريحة الفئة في البطاقة وفلاتر الفئات (أسماء الفئات من المصدر) |
| سمات عقارية (نوع العقار، غرف النوم، الحمامات، مساحة البناء) | **محاكاة حتمية** مشتقة من معرّف المنتج (`id`) في `Product`، لأن المصدر لا يوفر هذه الحقول. تُعرض في شاشة التفاصيل مع تنبيه للمستخدم وتُستخدم في فلاتر ورقة التصفية لمطابقة تصميم Figma. ليست بيانات حقيقية من الخادم. |

يُجلب الكتالوج كاملاً بطلب واحد (`limit=0`) ثم يُخزّن مؤقتاً وتُطبق عمليات البحث والفلترة والفرز محلياً عبر `CatalogQuery`. هذا قرار مقصود: يمنع الطلبات المتكررة، ويسمح بدمج فلاتر متعددة وتعديلات الجلسة على نفس المجموعة، بدل استخدام نقطة بحث الخادم لكل تغيير.

- واجهة DummyJSON هي واجهة محاكاة تجريبية (Mock API)؛ طلبات **POST وPATCH وDELETE** تُحاكي النجاح وتعيد كائنات معدلة لكنها **لا تحفظ التغييرات بصورة دائمة على الخادم**.
- للتغلب على هذا القيد وتقديم تجربة مستخدم واقعية ومتكاملة:
  - تحتفظ طبقة `CatalogRepository` بسجل تعديلات محلي أثناء مدة الجلسة (In-Memory Session Layer) لضمان بقاء التعديلات والإضافات ظاهرة للمستخدم طوال تشغيل التطبيق.
  - تعود البيانات لأصلها عند إنهاء التطبيق وإعادة تشغيله بالكامل، وهو السلوك الطبيعي والموثق لهذه الواجهة.
  - تُمنح العناصر المضافة محلياً معرّفات سالبة فريدة لتمييزها عن عناصر الخادم الأصلية.
